# examples · 真实数据成品

三张用公开真实数据出的成品图。数据不是编的，每个数字都能顺着来源核回去。

```bash
python3 examples/ex1_population.py       # 出图到 out/
python3 examples/fetch.py                # 重新抓一遍数据（平时不用跑）
```

## 为什么要有这一节

前面十三张图都用演示数据。演示数据是干净的：整数、短标签、量级适中——
于是一整类问题永远碰不到。这三个例子刚做完就撞出两条：

- **R1 从来没接 `decimals_for`。** 真实人口除成「亿」以后是 14.5094、
  3.40004，`num()` 给六位有效数字，同一列里并排出现「14.5094亿」和
  「3.40004亿」，读者会以为两者精度不同。R2/C1/C2/S3/D1/M2 早就统一了
  小数位，R1 是漏的那一个——demo 里全是整数，永远露不出来。
- **标题声称的数字要和图上画的用同一个函数算。** 例二的标题写「低 15.7 岁」，
  取的必须是 `quantile(vs, .5)`——也就是 D3 画那根中位线用的函数。
  图省事写 `vs[len//2]`，偶数样本下两者差半档：标题和图各说一个数，
  而这是最难被发现的那种错。

## 选型过程也是交付物

`SKILL.md` 第一节第 3 条要求「至少比较 3 个候选，写下淘汰理由」，理由是
**只记录用了哪张不算数**——选择过程本身是交付物的一部分。每个例子的文档
字符串里都写着那三个候选和淘汰理由，`tests/run.py` 的「选型记录」组机器判：
恰好一个「← 采用」、候选合计 ≥3，且淘汰理由必须落到数据形状或 catalog 的
失效条件上，不许是「感觉不合适」这种事后能编的话。

其中最值得看的一条淘汰，是**用数据淘汰的**：例二本来想画「人均 GDP vs
预期寿命」的 M2 散点带回归，实测皮尔逊 r 只有 0.620，取对数后才到 0.855——
这是条 Preston 曲线，在原始横轴上拟合一条直线属于第四节该拒绝的图。
M2 目前只做线性拟合，那就不该用它。**换图，而不是把非线性的数据硬塞进
线性的图里。**

## 数据

| 文件 | 指标 | 口径 |
|---|---|---|
| `data/population-2024.csv` | `SP.POP.TOTL` | 2024 年，人口前 12 |
| `data/life-expectancy-2023.csv` | `SP.DYN.LE00.IN` | 2023 年，217 个国家/地区 |
| `data/urbanization-1990-2023.csv` | `SP.URB.TOTL.IN.ZS` | 1990–2023，5 个经济体 |

来源为世界银行 World Development Indicators（CC BY-4.0），每份 CSV 第一行
写着指标编号与取数日期。`fetch.py` 会剔除「世界」「欧元区」「中等收入」
这类聚合口径——把它们和国家混在同一个标度上，等于一张图里放了两级行政层级。

**出图这一步不联网。** 数据落成 CSV 有两个原因：渲染必须离线且确定性
（`tests/run.py` 会验两次渲染字节一致），以及每个数字都可核对——
读者不必相信代码。
